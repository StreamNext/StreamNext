## Editing project.pbxproj by hand
SPM local packages auto-glob — dropping a new file into an existing package's `Sources/` needs **no** pbxproj change. Removing/adding an actual SPM *dependency* wired into Xcode does: touch all 5 sections (`PBXBuildFile`, Frameworks build phase, `packageProductDependencies` per target, top-level `packageReferences`, `XCRemoteSwiftPackageReference`/`XCSwiftPackageProductDependency` definitions). Verify with `plutil -lint` and a brace-count sanity check after every edit pass.

## Testing
- `xcodebuild test -only-testing:StreamNextTests` for unit/view-model tests — Swift Testing (`@Test`/`#expect`) is a reasonable default; view models tested directly (no mocked network layer) rather than through full integration is a pattern worth establishing from the first view model, not retrofitted later.
- A UI-test smoke suite (XCUITest) for the core user flow, once that flow exists, typically needs a live local backend plus test credentials — fall back to `build-for-testing` and say so explicitly if no backend is reachable.
- SwiftUI view bodies themselves aren't worth unit testing (no assertion value without a UI harness) — don't add tests for pure view composition with no new logic.
- **Never use screenshots to verify iOS UI** — burns context; use XCUITest assertions instead.
- **Never quit a running Xcode session** to fix stale state without asking first.
